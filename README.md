# 增强模块生成器

> **状态（2026-11-27）**：界面**按功能勾选**（支持拆分）。功能分组定义在 `features.psd1`，一个勾对应一个功能；**共用菜单的功能不必并组**——训练菜单骨架由生成器建，「传授经验」「学习技能」可以各自勾选。默认全选 = 现在的全量 29 项。参数在 `params.md` 里调，改完重新生成模块才生效；改模块后先跑 `check-module.ps1` 再进游戏。
>
> 当前生成结果（全选）就是游戏里的 `Modules\Native-Enhanced`（「原版增强」）：29 功能 / **669 脚本** / 3425 字符串 / 230 菜单 / 1390 变量；分享包 `Modules\warband-native-enhanced-v10.zip`（27.22 MB / 758 文件，26 功能含 Lua，11-26 打的；**不含整理物品、作弊菜单汉化与领主赎金**，要发带新功能的包需重打）。

按勾选的组 → 从**纯净 Native** 复制一份 → 应用补丁 → 生成独立模块。原版 Native 一个字节都不动。

双击 **`生成增强模块.bat`** 打开界面。目录**自包含**：整个 `modpack` 拷到别的电脑（约 1 MB）即可用，见「[打包到别的电脑](#打包到别的电脑自包含)」。

## 原理（为什么不直接改 Native）

战团一次只加载一个模块，所以独立模块是最干净的分享形态：原版不受影响、可随时切回、不会和别人的 Mod 打架。

生成器做的工作，本质上就是：

1. 把 `Modules\Native` 整个复制一份（排除 `_backup_*` 和 `- 副本.txt`）
2. 按功能顺序应用补丁，对副本的 txt 做增量修改：
   - 脚本只**往末尾追加**（不重排已有索引）
   - 新增菜单后，**全模块的菜单 ID 引用统一 +1**（scripts / conversation 里的跳转也要改）
   - 变量只追加（旧存档不变）
3. 改 `module.ini` 的显示名

所以补丁里没有写死任何脚本/菜单编号——都是按目标模块的实际情况算出来再填。

字符串还有一条额外规则：**WSE2 对 strings.txt 追加区有加载上限**（约「原生数 + 29」，实际更少），要显示的字符串必须排在追加区前部；生成器里的 `Reorder-AppendStrings` 会把不影响显示的调试串挪到末尾并重算所有字符串 token。`conversation.txt` 末尾追加同样不加载，对话行必须插文件前部。

```
  learnskill\        城镇训练学技能补丁（脚本 token + 学习菜单 + 触发器 + 中文菜单词条；训练菜单骨架由生成器 Apply-TrainingHost 建，提示走 Lua）
  reconcile\         冰释前嫌补丁（对话行 + 中英文词条，不改脚本/菜单）
  luck\              运气补丁（脚本 token + 菜单 + 字符串/中英文词条 + 触发器说明）
  defeat\            战败惩罚补丁（改 `party_remove_all_companions` / `loot_player_items` 常量；说明见目录 README）
  lua\               Lua 消息出口（main.lua + ms\ 52 个 Module System header/ID，生成时复制进模块 lua\msfiles）
  patrol\            友方巡逻队 + 村庄征募补丁（14 脚本：巡逻 9 + 征募 5，源码 patrol.asm 由 wb-asm.ps1 汇编；城镇菜单选项 + 2 个子菜单 + 触发器）
respec\              同伴洗点工具（独立，跟模块无关）
  warband-respec.bat
  warband-respec-gui.ps1
  npc-baseline.xlsx
```

> bat 里只用英文文件名（`manager.ps1`），因为 cmd 读 bat 时按系统代码页解析，中文文件名会变成乱码导致「找不到脚本、窗口一闪」。界面启动失败时看同目录的 `startup-error.txt`。

## 打包到别的电脑（自包含）

**整个 `modpack` 目录（约 1 MB，106 个文件）拷到任意可写位置就能直接用**，不依赖工作区其它目录：`patches\` 全部补丁、Lua 的 52 个 `msfiles`（`patches\lua\ms\`）、`features.psd1`（功能分组）、`check-module.ps1` 都在目录内；脚本里没有任何写死的机器路径（`$PSScriptRoot` 相对定位，游戏目录靠自动检测 + 界面浏览）。

对方机器需要的环境：

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（自带的 **Windows PowerShell 5.1** + `robocopy`，无需装额外运行时） |
| 游戏 | 骑马与砍杀战团，且 `Modules\Native` 是**纯净原版**（生成器只读它；Native 被改过会带进新模块） |
| WSE2 | **可选**：装了才能在游戏里看到 Lua 左下角提示；没装也能生成、游戏照常（只是无浮动提示） |
| 权限 | 游戏装在 `C:\Program Files (x86)` 时，用**管理员**运行 `生成增强模块.bat`（生成要写游戏目录） |

用法：解压/拷过去 → 双击 `生成增强模块.bat` → 「游戏目录」里浏览选中战团根目录（有 `mb_warband.exe` 的那层）→ 点「生成模块」。
生成器会把 `WSE2 SDK\` 里的扩展 opcode 追加进 `lua\msfiles`（没装 WSE2 就跳过，不影响 Native 功能）。

> 已验证：把 `modpack` 原样复制到 `tmp\modpack-test\` 后独立生成测试模块，六个核心数据文件与正式模块逐字节一致，`check-module.ps1` 十项全过（2026-11-24）。

## 物品原始价值说明（itemvalue）

引擎在显示物品属性时调用 `game_get_item_extra_text`（`scripts.txt` 里的原生脚本，参数 2 = `extra_text_id`，**0–7 共 8 行**；原版只用了 0/1：食物士气、书的智力要求与阅读进度）。生成器在体行末尾追加一个独立 try 块，占用 **2 号行**：

```
try_begin / eq :extra_text_id 2 / item_get_value reg1 :item_no /
set_result_string qstr_wb_item_value / set_trigger_result 0x999999 / try_end
```

- 文本：`Original_value:_{reg1}`（`quick_strings.txt`），中文 `原 始 价 值 ： {reg1}`（`languages\cns\quick_strings.csv`）
- 颜色：`0x999999`（灰，十进制 10066329）；想换颜色/行号改 `Apply-ItemValue` 里的 `2075 1 10066329` 与 `31 2 <extra_text_id> 2`
- 显示范围：**所有物品**（钩子分不清商店/背包），物品栏、商店交易、战利品等详情框通用
- 数值是 `item_get_value` 的**基础价值**，不含「极品/坚硬」等前缀加成——这正是“原始价值”的对照基准
- 不新增脚本/菜单/变量/触发器，旧档直接可读；`strings.txt` 不动（不占 WSE2 追加区上限）

## 技能相关优化说明（重要）

`skills.txt` 的 flags 字段：低 4 位是属性（0 力量 / 1 敏捷 / 2 智力 / 3 魅力），`0x10` 是队伍技能标志，`0x100` 是隐藏。

- **掠夺**：`17`（敏捷 + 队伍）→ `18`（智力 + 队伍）。属性只决定**面板图标和加点门槛**（技能等级不能超过对应属性 / 3），战利品数量仍是引擎按技能等级算的，不受影响。**已实测生效**（2026-11-20）。
- **骑术**：`1`（敏捷）→ `0`（力量）。同上，只改加点门槛与面板。
- **物品管理（实测结论）**：flags 从 `2` 改成 `18`（队伍）后，技能面板确实挪到了队伍技能栏，**但物品栏容量不变**——领袖技能只算玩家的效果是引擎硬编码的，社区用 TweakMB 改也失败。所以物品管理**保持领袖技能不动**。
计时结束由触发器置 Lua 消息（带技能号），左下角提示「你向同伴讨教诀窍，渐渐摸到门道，XX 技能 +1。」

**验证方法**：进游戏带一个某项技能比你高的同伴 → 城镇 → 训练 → 学习技能 → 点对应技能，等 8 小时看技能面板。

## 生成后自检（防 OOM）

生成完成后会自动跑 `check-module.ps1`，校验：

- `scripts.txt`：数量与行数一致；每个脚本「名字行 + 体行」，体行首 token = 语句数，逐条按 opcode 参数个数推进后**正好读完**；
- `strings.txt` / `simple_triggers.txt`：数量与行数一致；
- `menus.txt`：菜单行数 = 数量；
- `variables.txt`：无空行；
- 引用索引：数据文件里的脚本 / 菜单 / 字符串 / 变量 / 快速字符串 tag 都落在模块的实际数量内（拆分生成时最容易出问题的一项：新增 ID 按错的数量算，进游戏就指错对象或越界）；
- 中文 CSV：无 GBK 乱码。

任何一项打 `[X]` 就**别进游戏**：`Loading scripts...` 时弹 `EXCEPTION_OUT_OF_MEMORY` 基本全是 scripts.txt 结构错位造成的（语句数不对、脚本名/体错位、占位符没替换、末尾多空行）。也可以手动跑：

```powershell
powershell -ExecutionPolicy Bypass -File check-module.ps1 -ModuleDir "D:\SteamLibrary\steamapps\common\MountBlade Warband\Modules\Native-Enhanced"
```

**拆分回归（开发用，在能拿到本目录的工作区时）**：`scripts\scratch\test-split-groups.ps1` 会对每个组各生成一个测试模块并跑上面的自检，生成到工作区 `tmp\wbsplit` 里的模拟游戏目录，不碰真实游戏目录。

```powershell
powershell -File scripts\scratch\test-split-groups.ps1 -Only equip,mentor
powershell -File scripts\scratch\test-split-groups.ps1 -Combos "patrol+mentor;luck+claim"
```

## 注意

- 生成前**退出游戏**
- 新模块的存档目录是独立的；想接着玩原版存档，把 `我的文档\MountBlade Warband WSE2\Native\Savegames\*.sav` 复制到新模块对应的 Savegames 目录
- 生成后如果发现某功能不对，最省事的做法是重新生成（换个模块名）
- `simple_triggers.txt` 的数量**只能不变或增加**：存档记录触发器数量，减少后旧档读不了；停用功能用空触发器占位
- **换一组功能重新生成模块后**（比如上次全选、这次只勾换装），`simple_triggers.txt` 和各类 ID 会变，**旧存档可能读不出来**：建议换组合时换个模块名（或开新档）；同一组合同名重新生成不受影响
- 改完/生成后跑 `check-module.ps1`，全过再进游戏
